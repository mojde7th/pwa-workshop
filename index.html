چون Edge آن را مثل برنامهٔ کلاسیک ویندوز ثبت می‌کند، نه یک .lnk داخل استارت‌منو. برای همین Send to → Desktop روی چیزی که پیدا نمی‌کنی کار نمی‌کند.

  4. تیک Desktop را بگذار. اگر خواستی Start menu هم.

  3. ویندوز می‌گوید میانبر باید روی دسکتاپ ساخته شود. Yes.

service worker چیست، با دست

service worker یک فایل جاوااسکریپت است که مرورگر جدا از تب اجرا می‌کند. بین صفحه و شبکه می‌نشیند. درخواست GET را می‌تواند از شبکه بگیرد یا از Cache Storage جواب بدهد.

الان روی همین صفحه

  1. F12
  2. تب Application (در Chrome/Edge)
  3. چپ: Service Workers
  4. باید sw.js این پروژه را ببینی، Status معمولاً activated and is running
  5. پایین‌تر: Cache Storage → pwa-lab-v1 → باید index.html و manifest.json داخلش باشد

اگر آنجا چیزی نیست، یعنی هنوز ثبت نشده. دکمهٔ زیر را بزن، بعد همان تب را Refresh کن.

—

آزمایش قطع شبکه

  1. در DevTools تب Network → تیک Offline
  2. صفحه را Reload کن
  3. اگر service worker و Cache Storage پر باشد، همین صفحه باید باز بماند
  4. تیک Offline را بردار

این یعنی service worker: وقتی شبکه مرد، فایل‌های کش‌شده را می‌دهد. نظریه جدا ندارد. همان چیزی است که دیدی.

manifest باید ۲۰۰ بدهد

نصب PWA وقتی شروع می‌شود که مرورگر این فایل را با HTTP 200 بگیرد:

./manifest.json

اگر 404 یا Failed باشد، دکمهٔ نصب نمی‌آید. اگر service worker کهنه باشد، گاهی نسخهٔ قدیمی manifest را از کش می‌دهد؛ نصب کهنه می‌ماند.

دست ۱ روی همین فایل

—

دست ۲ در Network

  1. F12 → Network
  2. فیلتر: manifest
  3. Reload
  4. روی ردیف manifest.json کلیک کن
  5. نگاه کن: Status باید 200 باشد
  6. ستون Size: اگر نوشت (from ServiceWorker) یعنی از کش آمده، نه لزوماً فایل تازه روی دیسک

اگر 200 از ServiceWorker است و فایل روی گیت‌هاب عوض شده ولی آیکون/نام کهنه است:

  1. Application → Service Workers → Unregister
  2. Application → Storage → Clear site data
  3. Reload سخت:
Ctrl + F5

service worker کهنه

در sw.js این پروژه نام کش این است:

pwa-lab-v1

اگر فایل‌ها را عوض کنی و این نام را عوض نکنی، مرورگر ممکن است پوستهٔ قدیمی را نگه دارد. راه عملی که خودت ببینی:

  1. Application → Cache Storage → pwa-lab-v1 را باز کن
  2. یک فایل را از لیست نگاه کن
  3. Unregister روی service worker
  4. کش را Delete کن
  5. Reload؛ باید دوباره install شود و لیست تازه پر شود

در اپ واقعی، هر بار که app.js عوض می‌شود باید هم کوئری

app.js?v=36

هم نام CACHE در sw.js عوض شود. وگرنه نصب کهنه می‌ماند حتی اگر گیت‌هاب فایل جدید داشته باشد.

اگر GitHub بخوابد یعنی چه

GitHub Pages فایل‌های استاتیک را از همین مخزن روی دامنه‌ای مثل این سرو می‌کند:

https://USER.github.io/REPO/

اگر GitHub بخوابد یعنی github.com یا github.io جواب نمی‌دهد: DNS می‌میرد یا HTTP خطا می‌دهد. آن وقت:

  1. نصب تازه / دانلود فایل تازه: نمی‌شود
  2. اگر قبلاً این صفحه را باز کرده‌ای و service worker کش کرده: آفلاین همان پوسته باز می‌شود
  3. IndexedDB روی دستگاه توست؛ خوابیدن گیت‌هاب آن را پاک نمی‌کند
  4. همگام‌سازی به Apps Script ربطی به گیت‌هاب ندارد؛ آن به script.google.com می‌رود. گیت‌هاب خواب باشد، شیت ممکن است هنوز زنده باشد

شبیه‌سازی بدون منتظر ماندن برای خواب واقعی

  1. Network → Offline
  2. Reload
  3. اگر صفحه ماند، یعنی کش کار کرد. این همان سناریوی خواب گیت‌هاب برای فایل‌های استاتیک است
—

چرا یک پروندهٔ JS بدون bundler

bundler یعنی ابزارهایی مثل Vite / webpack: چند فایل را قاطی می‌کنند، خروجی dist/ می‌سازند، مرورگر آن خروجی را می‌خورد نه سورس تو.

GitHub Pages بیلد نمی‌زند مگر خودت GitHub Action بگذاری. چیزی که git push می‌کنی همان را وب‌سرور می‌دهد. پس اگر app.js را فرستادی، مرورگر همان را اجرا می‌کند.

روی همین لَب

  1. راست‌کلیک روی صفحه → View page source
  2. لینک manifest.json را باز کن
  3. در آدرس بار بزن:
./sw.js

متن خام sw.js را می‌بینی. هیچ npm run build وسط نیست. برای همین یک پرونده بدون باندلر: همان را که می‌فرستی همان را مرورگر می‌خورد.

نصب همین لَب به‌عنوان PWA

این پروژه جداست. آیکون اپ قبلی را دست نزن.

  1. این صفحه را در Edge باز کن (بعد از اینکه روی GitHub Pages باشد، یا حتی از فایل لوکال محدودیت دارد؛ نصب واقعی روی https است)
  2. آیکون نصب در نوار آدرس، یا ⋯ → Apps → Install this site as an app
  3. بعد میانبر را از edge://apps بساز، نه از پوشهٔ استارت‌منو
